# M5-11.15 Winner Qualification And Explicit Archive Handoff

## Objective And Scope

Implement the owner-approved product supplement: one exact-winner qualification
report, numerical decision explanations and a real opt-in COMPLETE Mode 4 archive
to Mode 5 coordinate path. Researchers choose whether to use these facilities.
Defaults, Ridge, mathematical methodology and financial execution stay unchanged.
The accepted parent research disposition remains intact; M5-12, installed
qualification, CI, push, merge, tag and publication are not launched.

## Identity And Ownership

`feat/mode5-diagnostics-first`. Existing `.venv` and native artifacts are reused.

## What The Researcher Receives

- The actual dictionary and original decision, not a retrospective substitute.
- Whole/annual returns, raw quality, registered utility, DD, daily loss ES and
  support/risk/quality flags; descriptive calendar consistency and null masks.
- Original close-mark exposure, fees/funding, engine closed-record units and
  authoritative fill support where supplied. Campaigns are not invented.
- Separately supplied state families with own source/readiness, unknown labels,
  monetary conservation and nonannualized conditional daily-return Sharpe.
- Exact-winner probe/stress references with measurement units, registered versus
  observed support and radius limits; no inference that finite probes certify a
  whole basin. Another diagnostic center is rejected.
- Numerical winner-minus-runner-up and same-pool eligible raw-best comparisons,
  original components, incumbent guard and ties. Registered original baseline
  packs add matched selected-path/account comparisons with explicit objective,
  seed, budget and initialization differences. One pair does not identify a
  causal sampler or risk-allocation effect.
- Coverage, missing evidence, limits and unchanged authority in the same record.

Annual attribution is not market-regime classification. User-supplied state
labels are not fitted by the reporter. U means the original registered utility,
not return or Sharpe. Public exports redact private fields; private readback is
explicit. Serialized reload requires an independently retained identity, and
renewed source verification requires the original inputs/current permissions.

## Complete-Archive Execution Proof

The public [synthetic example](../../examples/mode5_cross_mode_qualification.py)
registers 32 days, 768 hourly bars, two partial calendar years, capital 20,000,
leverage 1, allocation 0.5, configured fee 0.0005, slippage 0.0001, funding off
and seed 731. This records config values without renaming endpoint fee units.

It executes two weekly causal Mode 4 studies with two attempts each; retains the
original selected COMPLETE sampler trials and actual source/economic witnesses;
then freezes baseline/challenger Mode 5 packs before either outcome. Both use
four attempts, the same objective/selector/account/seed. The researcher names
fold 0 as the donor before execution. Coordinates, not old scores/model/account
state, enter the existing warm-start seam and consume the current budget.

Each successful smoke observes **12 proposals and 22 financial owner calls**:
Mode 4 4/11; Mode 5 baseline 4/6; challenger 4/5. The challenger has one actual
ordered warm start and one duplicate-effective-query reuse; the lower physical
count is not advertised as a speedup. Both arms select the **same dictionary**
in this fixture. This is a useful null control, not an economic superiority test.
Original result/pack reports agree, original marks match and the added synthetic
state family preserves attribution. Baseline activity is independently matched
to its original financial hashes.

Global Mode 5 uses its existing sealed current selection-policy clock for
post-window reviewed coordinates; it does not change Mode 4's historical IS
cutoff. Future, unknown-clock, wrong-purpose and NOT_BACKDATABLE prefix reuse
are denied. Current reporting access reauthorizes both baseline catalogs and
their full archive dependency graphs, not only the account witness.

The registered cumulative cap is 48 proposals/80 financial invocations. Three
successful source proofs cover initial integration, permission hardening and
the final exact full-account destination declaration. Together they consume
**36/66**, with zero private-alpha optimizers and zero model fits. One earlier
harness failure is retained: an exclusive JSON writer was mistakenly reused
for progress before the delegated first ask; it consumed zero actual proposals
or financial calls. Numbered immutable progress events replace that writer;
the failure is not relabelled PASS.
